# 独立运行时边界

[English](runtime-boundary.md) | 中文

Ai-harness 是一个**独立、事件溯源、工具治理、感知沙箱的 agent runtime（智能体运行时）**。Desktop、CLI（命令行界面）和 IDE 等产品界面是该运行时的客户端；它们不得成为 agent 逻辑的其他所有者。

## 架构不变量

1. **客户端不直接访问 Agent 内部。** 产品客户端通过 ACP（Agent Client Protocol）通信。程序化嵌入和自动化可在适当情况下继续使用 SDK 边界。
2. **可从 Session 模型重建对模型可见的持久状态。** 能够影响未来模型请求的长期状态必须在成为权威状态前持久化，或具有等效的持久化表示。
3. **agent 发起的外部副作用通过工具执行流水线。** 验证、钩子、权限、审批、守卫、沙箱策略、执行、结果归一化和审计均保留在同一条治理路径中。持久化、遥测、缓存、日志和索引等运行时维护工作不属于 agent 发起的外部副作用。
4. **权限和沙箱是不同的边界。** 权限决定操作是否应当运行；沙箱强制机制决定操作运行后能够实际访问什么。
5. **传输是适配器。** ACP 当前可使用 stdio，未来也可使用其他传输，而无需改变 Agent、Session、工具、权限或沙箱语义。

## 所有权

持久会话标识归 Session 持久化所有。ACP 连接只拥有实时运行时资源，例如活动 Agent 句柄和进行中的协议工作。客户端断开连接时可以取消任务、等待完全停稳、刷写并释放实时资源，但不得重新定义持久会话的生命周期。

因此，`session/close` 表示**释放活动资源**，而不是删除对话历史。在持久化 seam 自身具备删除能力之前，ACP 不会声明支持持久化删除。

## 依赖方向

```text
Clients
  |
  v
 ACP
  |
  v
Agent
  |
  +---- Session ---- Persistence
  |
  +---- Tools ------ Capability providers
  |
  +---- LLM
```

禁止的反向耦合包括 `Session -> ACP`、`Agent -> Desktop`、`Tool -> IDE/VSCode`、`Sandbox -> UI` 和 `LLM -> Client`。

## 客户端边界只进不退规则

仓库采用增量迁移，因此自动检查执行**只进不退规则**，而不是一次性重写。某个客户端界面的运行时依赖迁移到 ACP 后，该界面才会加入强制检查集合。一旦受到保护，它就不得直接导入以下运行时内部包：

- `@deepseek-ai/dsh-agent-loop`
- `@deepseek-ai/dsh-tools`
- `@deepseek-ai/dsh-session`
- `@deepseek-ai/dsh-sandbox`

Desktop 目前已受保护。CLI 尚未受保护，因为它的 ACP 迁移属于后续阶段；把 CLI 加入保护集合是迁移完成条件的一部分，不能以此为理由长期放行新的违规依赖。

检查器位于 `scripts/verify-client-runtime-boundary.ts`，并且应保持精简。不要用策略框架或第二套依赖图系统替代它。

## 协议边界

内部 Session 事件不是协议数据传输对象。ACP 必须把持久化或运行时读取模型投影为 ACP 专用的语义更新。历史回放与实时流必须共用相同的投影语义，确保重新连接行为不会偏离实时行为。

同样，ACP 数据传输对象仅存在于协议边界，不得泄漏到 agent loop（智能体循环）或持久化层。

## 会话并发约定

P0 不提供跨进程写入者互斥。同一持久会话一次只能在一个 Harness 进程中处于活动状态。客户端必须按顺序交接会话：先关闭实时 ACP 会话，再由另一个进程加载或恢复它。分布式锁、租约、CRDT 和本地守护进程会延后到出现真实的多客户端并发需求时再引入。

## 本阶段不包含的内容

不要仅为假设的未来需求引入 RuntimeManager、SessionManager、PluginManager、ExecutionManager、消息总线、分布式锁、守护进程框架、通用策略引擎、替代 ACP 协议、CRDT、容器编排器或远程传输。

优先使用现有原语和小函数。只有当新抽象能够消除已经出现的重复，或确实负责生命周期、并发或兼容性边界时，才引入它。
