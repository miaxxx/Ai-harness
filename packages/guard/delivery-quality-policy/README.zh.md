# @deepseek-ai/dsh-delivery-quality-policy

[English](README.md) | 中文

这是一个零配置提示词策略，把“基于证据停止”纳入每个已组装 agent 的轮次。它不修改 agent loop，不自行读取文件、不操作应用，也不自行裁决产物。策略要求模型把权威当前状态与用户请求结果进行比较；当结果已经满足时立即停止，并根据实际执行工作的类型采用相称的完成证据。

该插件依赖 `ctx.systemPrompt`，并以顺序 `120` 注册 `policy:delivery-quality` 段落。

```yaml
- id: delivery-quality-policy
  name: '@deepseek-ai/dsh-delivery-quality-policy'
```

该策略区分四种完成表面，而不是强行建立一个万能验证器：

- **只读问题与研究：** 与权威信息或用户指定来源一致、相关且有依据的回答即可作为证据；不能为了制造“验证动作”而无谓修改状态。
- **代码与文件修改：** 检查最终文件或 diff，并运行与请求行为相关的确定性检查，例如测试、typecheck 或 build。
- **外部状态与 GUI 修改：** 必须使用动作后的最新观察证明目标外部状态确实发生了请求的变化；工具调用本身成功并不等于结果成功。
- **生成或编辑产物：** 会话中存在内置 `delivery-verification` Skill 时加载并执行其类型化验收流程；需要时应对最终产物执行渲染、打开、重算或其他权威检查。

该策略明确拒绝陈旧或无关证据。过程叙述、仅文件存在、最后一次修改之前的截图、与目标无关的文档重复阅读，以及在状态未变化或动作被拒绝后盲目重试，都不能证明完成。检查失败时返回修复与重新检查；如果遇到真实的权限、用户输入、外部服务或外部状态阻塞，则如实报告，而不是伪装成成功。

该策略不新增 Session 事件、工具 schema、服务、可变状态、产物分类器或 completion certificate。模型可见提示词重建仍由 `dsh-system-prompt` 与请求 header 负责；现有 Skills 与确定性工具继续拥有各自领域的验证权威。

## 模型体验

### 结果证据段落

#### What the model sees

静态 `policy:delivery-quality` 段落建立一条统一停止规则：把最新权威状态与用户请求结果比较，只在证据表明结果仍未满足时继续；已经满足时不做多余修改并立即停止。随后分别说明只读、代码/文件、外部/GUI 与产物工作所需的完成证据。

#### Token effect

除非有效提示词被 complete 段落替换，否则每次请求都会携带固定策略文本。产物类型化流程在加载 `delivery-verification` 前不会进入提示词，因此无关参考内容不消耗 token。

#### KV Cache effect

在进程生命周期内保持前缀稳定。全局段落在 agent 创建前挂载且不再变化，因此后续轮次可以复用同一提示词前缀。

## 已知限制与暂缓事项

- 该策略约束模型流程；单项检查仍由确定性工具和权威外部观察裁决。这里刻意不引入通用宿主侧通过／失败分类器。
- complete persona 会按设计抑制其他全部提示词段落，其中包括本策略；这类 preset 自行拥有完整的完成策略。
- 未交付内置 Skills 的部署仍会获得通用证据规则，并直接使用可用工具。
