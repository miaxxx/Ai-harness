# Agent Note：Desktop 窗口拖动与路径附件

状态：已实现

[English](2026-09-03-desktop-window-drag-and-path-paste.md) | 中文

## 问题

macOS Desktop 窗口隐藏了原生标题栏，但替代它的顶部区域没有拖动能力。输入框也只能沿浏览器剪贴板链路接收图片，无法把从 Finder 复制的文件和文件夹加入已有附件栏。

## 决策

固定顶部空白区域使用 Electron 原生拖动区。该区域不包含应用控件，因此无需增加指针跟踪或自定义窗口移动 IPC。

启用且可编辑的输入框收到粘贴事件时，启用上下文隔离的 preload 才会观察剪贴板。它使用 Electron 支持的路径 API 解析原生 `File` 对象，并且只在剪贴板包含文件 URL、文件系统项目或图片时拦截原有文本／图片处理。纯文本继续使用输入框已有事务。捕获的选择范围和输入修订号把暂存项绑定到该草稿位置；草稿在异步完成前发生变化时，插入会被拒绝并释放暂存项，不会放到其他位置。

Desktop Main 验证类型化粘贴请求；Chromium 未提供路径时，再读取原生文件 URL 或 PNG 剪贴板数据。已有文件和文件夹保留原绝对路径并转为携带媒体类型与字节大小的 ACP resource link，不递归复制，也不解码媒介。只有没有源路径的位图会写入 Session 输入目录。每个暂存项都会成为带文件或文件夹图标和名称的结构化输入框内联引用，可置于普通文字之间并重复使用。输入框为图标和名称预留对称的胶囊两端空间，让胶囊保持在同一视觉行，光标跨过完整引用，删除操作也一次移除整个引用。引用序列化器将显示名称与不透明附件标记一同保留；Skill 引用使用结构化 Skill 标记，而不是退化成斜杠开头的文字。Main 进程按标记的精确顺序将每个附件标记替换为 ACP 内容块。刚发送的消息投影使用同一组有序部分，因此即使 Runtime 规范化文本，胶囊也会保留；回放的 resource link 与 Skill 都使用同一种紧凑胶囊渲染。

Desktop 提交提示词时，把本地受理与远程完成分开。Main 进程 IPC 请求一经受理，Renderer 就立即提交草稿，ACP 回合在后台继续。输入框可立即接收下一条草稿；内联活动提示被隐藏，因为对话记录已经负责展示实时回合和工具进度。后台提示词失败仍以输入框错误提示呈现；IPC 受理失败则保留草稿，因为尚未受理。粘性输入框座位会在底部和左右留白区域绘制与背景同色的遮罩，使用固定的透明到实色渐变，避免对话内容干扰正在编辑的输入面。

## 考虑过的替代方案

自定义基于指针的窗口拖动循环会重复 Electron 原生窗口行为，并引入额外的渲染进程到 Main 状态，因此顶部使用平台拖动区域。把每个粘贴路径复制到 Session 存储会使文件夹附件产生递归和高成本，并改变用户源文件的身份，因此已有文件系统项目保留为路径引用。通过 Computer Use 查看附件会引入无关的截屏权限，并丢失结构化文件系统证据，因此附件资源使用文件系统工具和格式专用工具。

## 结果

从 Finder 复制并粘贴到输入框可以附加任意格式文件和文件夹，无需把内容装入模型请求。用户可以把同一引用放在它修饰的文字旁，例如先放图片再放目标 HTML 文件，Agent 会在提示词的相应位置收到对应资源块。Agent 获得明确路径与媒体类型；`list_directory` 提供有界、非递归的目录证据和每个子项由提供方解析的路径，文件格式工具读取受支持文件。后续工具原样使用该路径，因此文件名中有意义的空白字符不会丢失。发送前删除内联引用会从提示词中移除暂存身份。如果源路径在提交前失效或不可访问，已有的明确失败行为仍会生效。
