# Agent Note：全局最终状态产物验收

Status: implemented

[English](2026-08-31-global-delivery-acceptance.md) | 中文

## 问题

自主任务可能产出看似合理的产物，却依据过程叙述或较早的检查结束，即使最后一次修改已经引入缺陷。视觉产物需要渲染后检查的证据，而代码、表格、研究与其他输出需要不同的确定性检查。把所有格式规则写进 agent loop 会让调度与产物工具耦合，并导致每增加一种格式都要修改 loop。

## 决策

- **由全局提示词策略拥有完成流程。** `@deepseek-ai/dsh-delivery-quality-policy` 贡献一个静态 `policy:delivery-quality` 系统提示词段落。agent 宣告完成之前，必须从请求中提取可观察检查项，在最后一次有意义修改后验证最终状态，修复失败，并重新执行受影响检查。它只报告实际执行的检查。
- **由一个内置 Skill 分流类型化验收。** `delivery-verification` 适用于产生产物的任务与有来源研究。入口保存共享验收循环，并分流到代码、浏览器 UI、文档、PDF、演示文稿、表格、图片与研究的聚焦参考文件。混合产物加载全部适用参考。这是渐进披露，不是八个重复同一触发条件与循环的目录条目。
- **复用现有 Skill 选择机制实施必加载规则。** `dsh-tool-skill` 已要求模型在执行任务操作前加载描述明确匹配任务的每个 Skill。全局策略会在目录中存在 `delivery-verification` 时点名该 Skill。所有完整产品 preset 都暴露共享内置 Skill 根目录；固定提示词的 Minimal preset 按设计没有 Skill 目录。因此不引入分类器或第二套路由服务。
- **Goal 提示词采用同一完成标准。** Goal 创建指引要求具体结果、约束与验证标准。每个 Goal Round 要求在最后一次有意义修改后收集当前证据；检查失败时先修复和重新检查，再调用 `update_goal complete`。Goal 持久格式与 agent loop 均不改变。
- **验证权威仍属于各格式。** 测试、渲染器、浏览器检查、工作簿重算、PDF 页面渲染与来源核查继续作为各自结果的权威。全局策略负责协调，不声称存在通用通过／失败信号。

## 验证

策略包测试固定注册段落、最终状态与修复循环要求以及卸载行为。Web preset 组装测试要求 Code、Work、Standard 与 Cordis 四种目录都包含内置 Skill。产品 headless keyless 快照运行真实组装轮次，并断言持久 request header 携带全局最终状态策略。Goal 包测试固定修改后的模型可见创建与续跑指引。Skill 校验检查新入口及其可发现参考文件。bundle、类型、文档与 workspace 门禁覆盖打包与发布。

## 曾考虑的方案

- **完成证书工具**：否决，因为模型填写的证书只是重述结论，没有独立验证。可信证书需要 harness 当前不拥有的格式提供方与产物所有权。
- **在 `update_goal complete` 前设置工具名白名单**：否决，因为工具名随部署变化，调用成功不代表产物质量，而且普通非 Goal 轮次会绕过它。
- **在 `agent-loop` 内检测产物**：否决，因为 loop 拥有模型与工具调度，不拥有文件格式或验收语义。已有提示词、Skill 与 Goal 扩展点足以覆盖该行为，无需修改 loop。
- **每种格式一个验收 Skill**：否决，因为每个条目都会重复同一最终状态修复循环与宽泛产物触发条件。一个路由入口降低目录成本与维护量，参考文件继续保留格式化指令。

## 后果

- 每个 base-bundle agent 都获得稳定完成标准；产品 agent 还会获得格式化验收流程。
- 视觉验收必须打开最终渲染输出检查，不能从源码或导出成功推断质量。
- 检查失败时工作保持活动，并进入下一轮修复与验证。无法使用的验证器必须报告为未验证限制，不能算作通过。
- complete persona 仍按设计抑制全部其他提示词段落，因此自行拥有完整完成策略。
