# Agent Note: You.com 是默认直连网页搜索提供方

Status: implemented

[English](2026-09-04-you-web-search-default.md) | 中文

## 问题

桌面组合通过 DeepSeek 搜索提供方公开标准 `web_search` 工具，即使部署选择了其他聊天模型提供方，网页检索仍绑定于 `DEEPSEEK_API_KEY`。产品需要独立的网页搜索默认值，同时不改变面向模型的工具，也不增加平行的搜索路径。

## 决策

`@deepseek-ai/dsh-web-search-you` 在 `ctx.web` 上注册 `you` 提供方 id。默认 ACP 与共享 bundle 组合选择该 id，并为 You.com 的直连 `POST /v1/search` API 使用 `apiKeyEnv: YDC_API_KEY`。该提供方每次搜索通过 `ctx.credentials` 解析该引用；服务缺失时使用启动环境。它将网页结果置于新闻结果之前映射为现有 `WebSearchResult`，因此 `@deepseek-ai/dsh-tool-web`、引用、Skill 与消费者继续使用现有请求和结果类型。

直连 API 保持为默认提供方路径。You.com 的免密钥免费服务是 MCP 端点；它不会作为隐式兜底，因为那会增加不相关的工具传输，并使已配置提供方的可用性依赖另一产品的配额和行为。

## 考虑过的替代方案

**保留 DeepSeek 作为默认值。** 不采用：网页检索仍会耦合于主模型凭据，无法独立配置搜索。

**将 You.com MCP 与现有提供方并列挂载。** 不采用：这会新增第二条面向模型的搜索路由，而不是切换标准 `web_search` 能力。

**在 `ctx.web` 后使用免密钥 MCP 兜底。** 不采用：直连提供方具有稳定的请求／结果映射和明确的凭据失败；静默切换传输和配额状态会使已配置提供方的行为变得不明确。

## 后果

桌面与共享 bundle 部署需要 `YDC_API_KEY` 才能使用网页搜索。缺失该值时，现有的「已选择提供方不可用」错误仍可直接处理。桌面端的**插件 → 插件配置 → 网页搜索**卡片经凭据领域写入同一个引用，只报告密钥是否已配置，绝不将字面值写进设置文档。直连 API 凭据在组合配置和包 README 中明确列出；部署仍可通过配置选择其他已安装提供方。单元测试覆盖结果映射、请求构造、取消、错误转换、注册和设置卡片的凭据写入；真实 API smoke 在没有密钥时自行跳过。
